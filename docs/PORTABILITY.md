# 宿主兼容合同

v0.1.0 不绑定厂商私有 SDK，不假定某宿主版本默认具备工具。每次新宿主检查：

| 能力 | 用途 | 缺失时 |
|---|---|---|
| 文件读写 | 资料、brief、成品与证据 | 只准备文本方案 |
| Python 3.10+ / 命令 | CLI、字体、图像与 SQLite | 交给具备执行能力的环境 |
| 私有终端/secret UI | 隐藏配置 Key | 用户在可信终端配置，不在聊天贴 Key |
| HTTPS 出站 | 调用配置模型 | 完成本地准备并报告限制 |
| 实际图片查看 | 最终审美与主体核验 | 不能代签验收 |
| 文档页图查看 | 核对图表、Logo 与扫描字 | 保持待复核 |
| 搜索（按任务需要） | 地域研究 | 可做无具体地标方案 |

| 宿主 | 接手方式 | 当前验证 |
|---|---|---|
| Codex 当前环境 | 仓库 + CLI + 看图 | 本地工程；真实聚合模型未测试 |
| WorkBuddy | 克隆仓库，复制 START_HERE，检查能力后调用 CLI | 未在该宿主实测 |
| 豆包工作 | 同上 | 未在该宿主实测 |
| 千万办公 | 同上，不假定支持 Skill/MCP 插件 | 未在该宿主实测 |
| Hermes | 仓库 + CLI；其已支持的技能机制可引用 skills/poster-production | 未实测；不改写 ~/.hermes |
| 其它智能体 | 读取宿主合同，调用同一核心 | 逐项验证 |

这是接入方式，不是厂商能力或兼容认证。V1 未实现 MCP server；未来可在同一核心上增加薄适配器。

可移植的是代码、契约和非私密风格规则。Key、客户素材、系统字体和本地验证状态不随 Git 传播。新机器先 doctor，再用真实业务样本验证，不继承旧机器 PASS。
