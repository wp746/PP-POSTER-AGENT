# 下一步逐步验收

## V0 工程

pytest、发布检查、构建和干净副本安装。确认 Git 没有 Key、客户素材、字体或维护者绝对路径。测试和 live evidence 不混用。

## V1 当前供应商

1. 用本副本已有配置，或隐藏配置，不扫描其它项目找 Key。
2. doctor 检查本地与声明；probe 只证明模型列出。
3. 用户提供第一张真实美食图、准确文案和预算，以这笔业务验证，不出无用途付费 smoke 图。
4. 先看 plan，选原图摄影区、提供的蒙版或明确接受 reference_edit。
5. run 后对照原图/A/B/文字/每个比例，记录失败并定向修复。

## V2 两类闭环

美食检查数量、表面、装盘、器皿；电话修改不重新生图；两个比例分别通过。活动提供真实文档/PPT、Logo/IP、目标和比例；核对页图、主题、地域与组织事实。

## V3 第一份风格

收到提示词与参考后，宿主真实看图，CLI 分析文本。检查去案例化、规则、能力边界，再用两个不同内容真实项目及所需比例验证；未测组合仍未测。

## V4 跨宿主

记录宿主/版本、系统、文件/执行/看图能力、安装日志、秘密配置方式、业务 brief、实际命令、图像与复核、恢复操作及产物哈希。安装了 Skill 不等于完成生产验收。

## V5 持续生产

按完整规格建立至少 24 个真实项目的起步评估，覆盖美食/活动、品类、风格、文字容量和比例。保留失败、重试、人工修改、实际费用与耗时；不选择性删除失败。世界级审美依作品对照和用户认可，不由替身或自评分证明。
